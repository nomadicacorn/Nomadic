# 스마일 시뮬레이터 (치과 상담용 MVP)

치과 대기실·상담실의 **큰 가로 모니터**나 **태블릿**에서 환자가 직접 입을 벌려 치아 사진을 찍으면,
**미백 · 레진 · 라미네이트 · 보철(크라운) · 교정** 치료 후 모습을 바로 비교해 보여주는 웹앱입니다.
상용 스마일 디자인 소프트웨어(예: Smile Designer Pro)의 핵심 상담 흐름(사진 → 입술/치아 영역 →
치아 템플릿·쉐이드·정렬 → 가이드선 → 전/후 비교)을 참고해 **설치 없이 브라우저에서 동작**하도록 만들었습니다.

> ⚠️ 결과는 상담 보조용 **시뮬레이션**이며 진단이나 실제 치료 결과를 보장하지 않습니다.

---

## 1. 실행 방법

필요한 것: **Node.js 18+** (추가 패키지 설치 없음, `npm install` 불필요), 최신 Chrome / Edge / Safari.

```bash
git clone <이 저장소>
cd Nomadic
npm start            # → http://localhost:8080
```

- **같은 PC에서 사용(모니터+웹캠)**: 브라우저에서 `http://localhost:8080` 접속 → 카메라 바로 사용 가능.
- **태블릿 등 다른 기기에서 접속**: 브라우저 정책상 카메라는 HTTPS에서만 동작합니다. 원내 PC에서 인증서를 만들어 실행하세요.

  ```bash
  # mkcert 예시 (https://github.com/FiloSottile/mkcert)
  mkcert -install
  mkdir -p certs && mkcert -key-file certs/key.pem -cert-file certs/cert.pem 192.168.0.10 localhost
  SSL_KEY=certs/key.pem SSL_CERT=certs/cert.pem npm start   # → https://192.168.0.10:8080
  ```
  태블릿에는 mkcert 루트 인증서를 설치해야 경고 없이 접속됩니다.
- Node 없이 확인만 하려면: `python3 -m http.server 8080` (보안 헤더는 빠지지만 HTML의 CSP는 적용됨).
- **키오스크 모드**: 시작 화면 우하단 ⚙️(직원 설정) → "전체 화면", 또는 Chrome `--kiosk http://localhost:8080`.

- **단일 HTML 파일로 배포**(USB·사내 정적 호스팅·서버 없이 더블클릭):
  ```bash
  node scripts/build-single.mjs              # → dist/smile-simulator.html (CSP 포함, 오프라인 동작)
  node scripts/build-single.mjs out.html --hosted   # 실시간 카메라가 막힌 호스팅 환경용
  ```
  실시간 카메라를 쓸 수 없는 환경(권한 거부, 호스팅 페이지 등)에서는 `카메라로 촬영하기`가 자동으로
  **기기 기본 카메라 앱**(태블릿/폰) 또는 파일 선택으로 대체됩니다.

테스트:

```bash
npm test   # 색 변환, 치아 분할, 미백, 레진, 교정 워핑, 핀 제안, 템플릿 단위 테스트 (Node 내장 test runner)
```

## 2. 사용 흐름

1. **시작/동의** – 개인정보 안내 확인 후 동의 체크 → `카메라로 촬영` 또는 `사진 불러오기` (`데모 사진으로 체험`은 합성 이미지).
2. **촬영** – 화면의 점선 타원 안에 치아를 맞추고 "이~" → 3초 카운트다운 후 자동 촬영. 확대 슬라이더로 거리 보정.
3. **치료 선택** – 큰 카드 6종: 치아 미백 / 레진 / 라미네이트 / 보철(크라운) / 치아 교정 / 교정+미백.
4. **비교** – 원본·결과·슬라이더 비교·나란히 보기, "누르고 있으면 원본", 정중선·황금비율·스마일라인·치아영역 가이드.
5. **세부 조정(직원)** – 쉐이드(현재→목표), 강도, 템플릿 형태(오벌/스퀘어/트라이앵글)·개수·폭·길이·곡선·황금비율,
   교정 핀(자동 제안/직접 찍기/목표 직접 조정), 교정 정도.
6. **영역 보정** – 입술 안쪽 윤곽 점 드래그, 치아 영역 브러시 추가/지우기, 인식 감도, 얼굴 정중선 지정.
7. **상담 종료 · 사진 삭제** – 메모리의 모든 이미지 버퍼를 0으로 덮어쓰고 시작 화면으로.

## 3. 개인정보 보호 설계

| 항목 | 구현 |
|---|---|
| 전송 차단 | 모든 처리는 브라우저 메모리에서 수행. 업로드 API 없음. CSP `connect-src 'none'`로 **fetch/XHR/WebSocket 자체가 불가** |
| 저장 안 함 | 사진은 localStorage/IndexedDB/쿠키에 저장하지 않음 (직원 설정값만 localStorage) |
| 자동 삭제 | 무입력 N분(기본 3분) → 10초 경고 → 삭제. "상담 종료" 버튼, 페이지 이탈 시 삭제, (옵션) 탭 전환 시 즉시 삭제 |
| 메모리 정리 | ImageData·마스크 버퍼 `fill(0)`, 캔버스 1×1로 축소, 카메라 트랙 즉시 정지 |
| 메타데이터 | 불러온 사진은 픽셀만 캔버스로 옮기므로 EXIF(GPS·기기정보) 제거 |
| 저장 기능 | 기본 꺼짐. 직원 설정에서 허용 시에만 로컬 다운로드, 파일명에 환자 정보 없음, 이미지에 "시뮬레이션" 문구 삽입 |
| 서버 헤더 | `server.js`: CSP, `Permissions-Policy: camera=(self)`, `no-store`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` |
| 최소 수집 | 촬영 시 입 주변만 크롭해 처리 (얼굴 전체를 보관하지 않음) |

자동화 테스트에서 페이지 로드~촬영~시뮬레이션 전 과정 동안 **외부 네트워크 요청 0건**을 확인했습니다.

요약은 아래와 같고, 상세 설명과 연동 설계는 [`docs/FEATURES.md`](docs/FEATURES.md)를 참고하세요.

|---|---|
| 가이드 촬영·카운트다운·크롭 | 얼굴/입술 랜드마크 자동 검출 |
| 입술 안쪽 윤곽(가이드 + 수동 조정) | 치아 개별 분할 + FDI 치식 번호 |
| 치아 영역 분할(색상 통계 Otsu + 브러시 보정) | 생성형 AI 기반 사실적 결과 합성 |
| 쉐이드 추정(참고용)·미백 | 부정교합 분류·치료 적합도 판단 |
| 레진: 착색 제거·틈(정중이개) 메움 | 3D 얼굴/구강스캔(STL) 연동 |
| 라미네이트: 표면·색 균일화 | |
| 보철 스마일 템플릿(형태 3종, 황금비율, 자동 맞춤) | |
| 교정: 절단연 핀 자동 제안 + 대칭·스마일아크 정렬 + MLS 워핑 | |
| 전/후 비교, 정중선·황금비율·스마일라인 가이드 | |

## 5. 폴더 구조

```
index.html            화면(시작/촬영/스튜디오) + CSP
css/styles.css        대형 터치 UI, 가로 모니터·세로 태블릿 반응형
js/core/              DOM 없는 순수 처리 모듈 (Node 테스트 가능)
  color.js            sRGB↔Lab
  geometry.js         폴리곤·스플라인·래스터화
  imageops.js         블러·정규화 컨볼루션·모폴로지·Otsu·연결요소
  segmentation.js     치아 분할, 교정 핀 자동 제안
  shades.js           쉐이드 가이드(근사 Lab) / 추정
  effects.js          미백·레진·라미네이트·템플릿 합성
  ortho.js            이상적 배열 계산 + MLS 워핑
  template.js         치아 형태 라이브러리·배치
  pipeline.js         치료 조합 파이프라인
js/ai/provider.js     AI 연동 어댑터 인터페이스 + 기능 상태표
js/ui/                app.js(컨트롤러), camera.js, privacy.js, demo.js
server.js             무의존 정적 서버 (HTTP/HTTPS, 보안 헤더)
tests/                단위 테스트 (합성 이미지 사용, 실제 환자 사진 없음)
```

## 6. 알려진 한계

- 치아 분할은 색상 규칙 기반이라 조명이 어둡거나 잇몸 노출이 많으면 정확도가 떨어집니다 → `영역 보정` 탭의 브러시/감도로 보정.
- 교정 시뮬레이션은 2D 이미지 변형이므로 치아 회전·전후(순설) 이동, 발치 공간 폐쇄는 표현하지 못합니다.
- 쉐이드 Lab 값은 근사치이며, 사진 조명에 따라 추정 쉐이드가 달라집니다.
- 의료기기 인증 대상 기능(진단)은 포함하지 않습니다.
