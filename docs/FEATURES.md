## 2. AI 연동 설계 (향후)

연동 지점은 `js/ai/provider.js`의 `SmileAIProvider` 인터페이스입니다.

```js
class SmileAIProvider {
  detectLipContour(image)              // → [{x,y}] 입술 안쪽 윤곽
  segmentTeeth(image, lipPoly, opts)   // → segmentTeeth()와 동일 형식 {mask, binary, inside, insideSoft, curve, bbox, stats}
  detectTeethInstances(image, seg)     // → [{fdi, polygon, incisalPoint}]
  estimateShade(image, seg)            // → {id, L, a, b}
  refineResult(before, after, mask, plan) // → 생성형 리파인된 결과
}
```

현재는 `LocalHeuristicProvider`(규칙 기반)만 있으며, UI는 `js/ui/app.js`의 `segment()` 한 곳에서 분할을 호출합니다.

### 권장 방식: 기기 내(on-device) 추론 — 개인정보 원칙 유지
1. **입술/얼굴 랜드마크**: MediaPipe Face Landmarker(WASM) — 모델 파일을 `models/`에 **동봉**해 외부 CDN 미사용.
2. **치아 분할/번호**: 공개 치아 데이터셋 또는 원내 동의 데이터로 학습한 경량 U-Net / YOLO-seg → ONNX 변환 → ONNX Runtime Web(WebGPU/WASM).
3. **생성형 리파인**: 경량 인페인팅 모델(기기 성능에 따라 선택). 규칙 기반 결과를 "가이드"로 주고 마스크 영역만 다시 그리게 하여 환자 얼굴 정체성 유지.
4. CSP는 그대로 `connect-src 'none'`, `script-src 'self' 'wasm-unsafe-eval'` 정도만 추가.

### 서버 추론이 불가피한 경우 (비권장)
- CSP `connect-src`에 원내 서버 도메인 **하나만** 허용, 외부 클라우드 직접 호출 금지.
- 입 영역만 크롭·비식별화하여 전송, 별도 전송 동의 화면, 서버 메모리 처리 후 즉시 폐기(디스크 저장 금지), 접근 로그 관리.
- 개인정보보호법(민감정보·영상정보) 및 의료법 검토 필요.

## 3. 참고한 상용 소프트웨어 기능 대응

| 상용 스마일 디자인 SW의 일반 기능 | 본 MVP |
|---|---|
| 환자 사진 불러오기·보정 | 촬영 가이드/불러오기, 입 영역 자동 확대 |
| 입술선·치아 영역 지정 | 입술 윤곽 점 편집, 치아 브러시 |
| 스마일 라이브러리(치아 형태 템플릿) | 오벌/스퀘어/트라이앵글 템플릿, 개수·크기·곡선 |
| 치아 색(쉐이드) 변경 | 쉐이드 가이드 기반 현재→목표 이동 |
| 측정 가이드(정중선·황금비율) | 정중선, 황금비율 격자, 스마일라인 |
| 전/후 비교 프레젠테이션 | 슬라이더·나란히·누르고 보기, (허용 시) 비교 이미지 저장 |
